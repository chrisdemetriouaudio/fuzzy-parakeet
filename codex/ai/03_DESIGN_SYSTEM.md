Design System

Purpose

This document defines the visual and interaction language for ChrisDemetriou.com Version 2.

It exists to ensure every page feels like part of one coherent product rather than a collection of individually designed pages.

Consistency is more important than novelty.

⸻

Design Philosophy

The website should feel like a premium enterprise SaaS product.

Not a personal portfolio.

Not a CV.

Not a marketing site.

Every component should communicate:

* clarity
* confidence
* craftsmanship
* credibility

The visual language should reinforce Chris’s ability to simplify enterprise complexity.

⸻

Design Principles

Clarity First

The interface should always reduce complexity.

Every screen should answer one primary question.

If something requires explanation, investigate whether it should instead be communicated visually.

⸻

Cognitive Simplicity

Design for scanning.

Reading should be optional.

Prioritise:

* whitespace
* typography
* hierarchy
* grouping
* progressive disclosure

Avoid visual overload.

⸻

Premium Restraint

Avoid visual trends that will quickly date.

No unnecessary gradients.

No decorative glass effects unless they genuinely improve the interface.

No excessive animation.

Confidence comes from simplicity.

⸻

Visual Inspiration

Reference products:

* Apple
* Linear
* Vercel
* GitHub
* Raycast
* Notion

These products share:

* exceptional typography
* spacing discipline
* restrained colour
* thoughtful motion
* clarity

Those qualities should guide this project.

⸻

Colour Philosophy

Dark Mode is the primary brand experience.

Avoid pure black.

Use carefully balanced dark neutrals.

Similarly avoid pure white for body text.

Prioritise comfortable reading over maximum contrast.

The palette should feel calm rather than dramatic.

⸻

Theme System

Support:

* Dark
* Light

Requirements:

* seamless switching
* preference persistence
* system detection
* accessible contrast
* consistent branding

Both themes should feel intentionally designed.

⸻

Typography

Typography carries the brand.

It should feel editorial rather than corporate.

Hierarchy should remain obvious even without colour.

Guidelines:

* generous line height
* large headings
* comfortable measure
* restrained font weights
* minimal decorative styles

Avoid:

* dense paragraphs
* overly small text
* multiple typefaces

⸻

Spacing

Whitespace is a design tool.

Every component should have room to breathe.

Prefer fewer elements with more space over crowded layouts.

Spacing should communicate hierarchy naturally.

⸻

Grid

Content should align to a consistent responsive grid.

Layouts should feel balanced rather than rigid.

Never stretch text across excessively wide containers.

⸻

Navigation

Navigation should remain calm and unobtrusive.

Primary navigation:

* Enterprise Technology
* Creative Media
* Resources

Utility controls:

* Theme
* Read Aloud
* Focus Mode
* Reading Preferences

The navigation should never dominate the experience.

⸻

Hero

The hero introduces an insight.

Not Chris.

Not his experience.

Not his job title.

The opening statement should stop visitors scrolling.

Only afterwards should Chris gradually appear.

⸻

Cards

Cards should communicate one idea.

Avoid:

* information overload
* unnecessary icons
* decorative borders

Cards should be:

* clean
* spacious
* consistent
* accessible

⸻

Tabs

Tabs separate:

Enterprise Technology

Creative Media

Technology remains the default.

Switching tabs should feel smooth without disrupting context.

⸻

Buttons

Buttons should communicate importance through hierarchy rather than colour alone.

Primary CTA:

high emphasis

Secondary CTA:

lower emphasis

Avoid excessive button styles.

⸻

Enterprise Diagrams

Enterprise diagrams become a signature part of the brand.

Use diagrams to explain:

* dependencies
* information flow
* enterprise ecosystems
* release readiness
* operational readiness

Avoid generic network graphics.

The diagrams should teach.

⸻

Information Flow

One of the defining components.

Information flows from technical disciplines.

Chris analyses context.

Relevant information flows onward.

Animation should communicate:

* dependency awareness
* judgement
* contextual understanding
* enterprise coordination

The animation should never look decorative.

⸻

Timelines

Avoid traditional employment timelines.

Instead create:

* enterprise journeys
* project lifecycle visualisations
* technology evolution
* learning journeys

The emphasis should remain on thinking rather than chronology.

⸻

Photography

Photography should feel editorial.

Preferred characteristics:

* authentic
* natural
* thoughtful
* technically credible

Avoid:

* stock photography
* exaggerated poses
* folded arms
* artificial smiles

Use placeholders until final photography is commissioned.

⸻

Icons

Icons should support understanding.

Never decorate.

Prefer simple outline icons.

Consistency is more important than uniqueness.

⸻

Motion

Motion should communicate.

Never distract.

Use motion to:

* reveal information
* explain relationships
* guide attention
* reinforce hierarchy

Animations should remain subtle.

⸻

Reading Experience

Provide premium reading controls.

Focus Mode

Read Aloud

Reading Preferences

These should feel like integrated product features rather than accessibility plugins.

⸻

Cookie Experience

Cookie consent should match the overall design language.

Elegant.

Minimal.

Respectful.

Easy to dismiss.

Easy to revisit.

⸻

Empty States

Every empty state should remain useful.

Explain what belongs there.

Where appropriate include a call-to-action.

Never leave blank space unexplained.

⸻

Accessibility

Every component must support:

* keyboard navigation
* visible focus
* semantic markup
* screen readers
* reduced motion
* sufficient colour contrast

Accessibility should never require a separate implementation phase.

⸻

Responsive Behaviour

Every component should define behaviour across:

* mobile
* tablet
* laptop
* desktop
* ultra-wide

No component should rely solely on hover interactions.

⸻

Reusable Components

The following should exist as reusable components:

* Navigation
* Hero
* CTA
* Tabs
* Timeline
* Cards
* Metrics
* Pull Quotes
* Enterprise Diagram
* Information Flow
* Testimonials
* Theme Toggle
* Focus Mode
* Read Aloud
* Reading Preferences
* Cookie Banner
* Footer

⸻

Component Checklist

Every component should answer:

Why does this exist?

Does it reduce cognitive load?

Does it reinforce positioning?

Is it accessible?

Can it be reused?

Does it improve understanding?

If the answer is no, reconsider whether it belongs.

⸻

Final Principle

The design system should make every future page feel like it belongs to the same product.

Visitors should experience consistency without noticing it.

That is the mark of a successful design system.
